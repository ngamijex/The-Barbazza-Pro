### **2. Payment Summary Table**

For each barber, displays:

```
┌──────────────────────────────────────────────────────────────────────┐
│  Barber Code  │  Name    │  Gross    │  Rate  │  Commission         │
│  B001         │  John    │  500,000  │  40%   │  200,000           │
│                                                                        │
│  Recruitment  │  Credit  │  Total    │  NET SALARY                  │
│  -10,000      │  -5,000  │  -15,000  │  185,000 RWF                 │
└──────────────────────────────────────────────────────────────────────┘
```

**Columns Explained:**
- **Gross Income** - Total revenue generated by barber
- **Commission Rate** - Barber's percentage (usually 40%)
- **Commission Earned** - Gross × Rate
- **Recruitment Deduction** - Monthly deduction for recruitment advance
- **Credit Deduction** - Sum of all approved credits' monthly deductions
- **Total Deductions** - Recruitment + Credits
- **NET SALARY** - Final payment amount (Commission - Deductions)

---

## 💸 **Payment Calculation Logic:**

### **Step 1: Calculate Commission**
```
Gross Income = SUM(all transactions for the month)
Commission Earned = Gross Income × (Commission Rate / 100)

Example:
Gross = 500,000 RWF
Rate = 40%
Commission = 500,000 × 0.40 = 200,000 RWF
```

### **Step 2: Calculate Deductions**

**A. Recruitment Deduction**
```
Monthly deduction from recruitment advance
- Set when barber was recruited
- Fixed amount per month
- Example: 10,000 RWF/month
```

**B. Credit Deductions**
```
Sum of all approved credits' monthly deductions
- Barber may have multiple active credits
- Each credit has its own monthly deduction
- Example: Credit 1 = 3,000 + Credit 2 = 2,000 = 5,000 RWF
```

**Total Deductions:**
```
Total = Recruitment Deduction + Credit Deductions
Example: 10,000 + 5,000 = 15,000 RWF
```

### **Step 3: Calculate Net Salary**
```
Net Salary = Commission Earned - Total Deductions
Net Salary = MAX(result, 0)  # Cannot be negative

Example:
Commission = 200,000 RWF
Deductions = 15,000 RWF
Net Salary = 185,000 RWF
```

## 🗄️ **Database Operations:**

### **Transaction-Safe Processing:**

```sql
BEGIN TRANSACTION;

-- For each barber:

-- 1. Insert payment record
INSERT INTO monthly_salaries (
  barber_id, month, year, 
  gross_income, commission_earned,
  recruitment_deduction, credit_deduction,
  net_salary, paid_date, status
) VALUES (...);

-- 2. Update recruitment balance
UPDATE barbers
SET advance_remaining = advance_remaining - advance_monthly_deduction
WHERE barber_id = ?;

-- 3. Update each credit balance
UPDATE barber_credits
SET remaining_balance = remaining_balance - monthly_deduction
WHERE credit_id = ?;

COMMIT;  -- Or ROLLBACK on error
```

## 📊 **Balance Updates:**

### **1. Recruitment Balance Update**

**Before Payment:**
```
Recruitment Balance: 100,000 RWF
Monthly Deduction: 10,000 RWF
```

**After Payment:**
```
New Balance = 100,000 - 10,000 = 90,000 RWF
✓ Updated in barbers.advance_remaining
```

**When Balance Reaches Zero:**
```
Balance: 5,000 RWF
Deduction: 10,000 RWF
New Balance: MAX(5,000 - 10,000, 0) = 0 RWF
✓ Recruitment advance fully paid!
```

### **2. Credit Balance Update**

**Before Payment:**
```
Credit 1: 20,000 RWF remaining, 5,000 RWF/month
Credit 2: 15,000 RWF remaining, 3,000 RWF/month
```

**After Payment:**
```
Credit 1: 20,000 - 5,000 = 15,000 RWF
Credit 2: 15,000 - 3,000 = 12,000 RWF
✓ Both credits updated in barber_credits table
```

**When Credit is Paid Off:**
```
Credit: 3,000 RWF remaining, 5,000 RWF/month
New Balance: MAX(3,000 - 5,000, 0) = 0 RWF
✓ Credit fully paid! (will not be included in next month)
```

## 🛡️ **Safety Features:**

### **1. Confirmation Dialog**
```
Requires explicit confirmation before processing
Shows summary of what will happen
Clear warning about irreversibility
Two-step process (button → confirm)
```

### **2. Database Transactions**
```
All operations in single transaction
If ANY operation fails:
  ✓ Entire transaction rolls back
  ✓ No partial updates
  ✓ Database remains consistent
  ✓ Error message shown to manager
```

### **3. Duplicate Prevention**
```
Months already processed are excluded from dropdown
Cannot close same month twice
System checks monthly_salaries table for existing records
```

### **4. Minimum Salary Protection**
```
Net Salary = MAX(Commission - Deductions, 0)
Cannot pay negative amount
If deductions exceed commission, salary = 0
Protects against over-deduction errors
```

## 🗂️ **Database Schema Impact:**

### **monthly_salaries Table:**
```sql
CREATE TABLE monthly_salaries (
  salary_id SERIAL PRIMARY KEY,
  barber_id INT REFERENCES barbers(barber_id),
  month INT,
  year INT,
  gross_income DECIMAL(10,2),
  commission_earned DECIMAL(10,2),
  recruitment_deduction DECIMAL(10,2),
  credit_deduction DECIMAL(10,2),
  net_salary DECIMAL(10,2),
  paid_date TIMESTAMP,
  status VARCHAR(20) DEFAULT 'paid'
);
```

### **barbers Table Updates:**
```sql
-- advance_remaining is updated
UPDATE barbers
SET advance_remaining = advance_remaining - advance_monthly_deduction
WHERE barber_id = ?;
```

### **barber_credits Table Updates:**
```sql
-- remaining_balance is updated
UPDATE barber_credits
SET remaining_balance = remaining_balance - monthly_deduction
WHERE credit_id = ? AND remaining_balance > 0;
```
